# アーキテクチャ

## レイヤー

- Application: 資格情報ストアと更新スケジューラーの契約、インメモリの資格情報実装。UIやプラットフォームに依存しません。
- Infrastructure: OS資格情報ストア（Windows Credential Manager、Linux `secret-tool`）、設定ストア（ユーザー別データ領域の`settings.json`）、更新スケジューラー、パス解決。
- UI: Avaloniaアプリケーション。プレゼンテーション（ViewModel）、利用量APIの読み取りポート（HTTP）、ローカライズ、トレイ、composition rootを含みます。
- Collector: 単体で動くLinux x64向けのNative AOT実行ファイル。標準入力の`tokscale graph`ドキュメントをスナップショットへ正規化し、利用量APIへ送信します。アプリ側のどのプロジェクトも参照しません。
- Usage.Api: Cloudflare Workers + Hono + D1で動くTypeScriptパッケージ。.NETソリューションには含まれず、アプリとはHTTP契約だけで結びつきます。

`QuotaSight.Core`は利用枠モデルとともに削除されました。現在、依存関係を持たないドメイン層は存在しません。

## 依存方向

```
UI ──────────> Application
 │
 └──────────> Infrastructure ──> Application

Collector（単体） ──HTTP(PUT)──> Usage.Api ──> D1
UI ───────────────HTTP(GET)──> Usage.Api
```

UIはApplicationとInfrastructureに依存します。InfrastructureはApplicationに依存し、Applicationは他プロジェクトに依存しません。Collectorは何も参照せず、Usage.Apiは.NETソリューションの外にあります。UIへネットワーク、ファイルシステム、OS固有の処理を持ち込まず、それらはInfrastructureとUIの読み取りポートに閉じ込めます。

## データの流れ

### 送信（Collector → 利用量API）

1. Collectorはローカルで上流CLI（`tokscale graph`）の集計を標準入力から読み取り、許可した項目だけを日次スナップショットへ写像します。既定は wire v1(`schemaVersion` 1、`adapterVersion`、`generation`、`collectedAt`、`bucketTimeZone`、`coveredRange`、`days[{date,totalTokens}]`)で、日次合計だけを送ります。オプトインの wire v2(`schemaVersion` 2)では、その日に利用した client / provider / model の識別子(正規化済み・小文字・不明は空文字)と、5成分(入力、出力、cache read、cache write、reasoning)のトークン内訳を `keys` と `days[].parts` として送り、受信側は `usage_part` に日単位の集合として保存します。どちらの版でも、プロンプト、応答本文、コスト・料金、メッセージ数、ファイルパス、パスらしいモデルID、アカウント表示名は送りません。モデル名を送るかどうかは運用者が `--wire-schema` で選び、既定は送らない v1 です。
2. Collectorは送信済みrevisionより大きいrevisionでスナップショットを送信します。受信側は世代・revision・日次合計の単調性をトランザクション内で検証し、受理済みの合計を下げません。下げる必要があった件数は受領応答の`ignoredReductions`として返します。v2 の内訳は日単位の集合として扱い、受信した Σparts が保存済みより大きい日だけを入れ替えます。同値の日は古い集合が勝ち、下げた日数と挿入した行数を `ignoredPartReductions` と `changedParts` として返します。
3. 送信はリアルタイムではなく、Collectorは1〜6時間間隔で動く前提です。`--preview`が既定で、`--send`は明示したときだけ行います。

### 読み取り（アプリ ← 利用量API）

1. UIは日次合計と、Collectorごとの`lastReceivedAt`（active generationで最後に受理した時刻）を読み取ります。内訳は `GET /v1/usage/breakdown` から、キー別の合計と、日ごとの「その日の合計 / 内訳で説明できた分」を読みます。読み取りは collector の active generation だけを対象にし、旧 generation の行は保存されたまま読み取り API では返りません（過去 generation を読む手段は未提供）。読み取りポートは契約違反を推測で補正せず、失敗を型付きで分類します。
2. ViewModelは最も古い`lastReceivedAt`を鮮度として表示し、名前付きのしきい値（12時間）を超える場合は遅延データとして明示します。読み取りに失敗した場合、前回の行・合計・鮮度を保持したままstale状態と失敗種別を表示し、値を消したりゼロに置き換えたりしません。
3. 未認証（401）、権限不足（403）、対象なし（404）、一時的な失敗（timeout、接続失敗、429、5xx）、契約違反の応答、リダイレクトは別の状態として扱い、それぞれ固定文言で案内します。403 とリダイレクト（追従しない）は、どちらも設定画面でエンドポイントと資格情報を見直す導線に結びつけます。サーバー側の設定不備は、資格情報の誤りと区別できるよう 503 `auth_unconfigured` として返し、クライアントは一時的な失敗として再試行します。実環境の Cloudflare Access の応答は、2026-11-22 に1つのアカウント（strict service token authentication オン、`Service Auth` のみのポリシー、Managed OAuth オフ）で観測した範囲では、資格情報なしが HTTP 403（`text/html` の Access エラーページで、Worker には到達しない）、Client ID が正しく Secret が誤りが HTTP 401、ローテーション後の失効済み Secret も HTTP 401 で、302 は出ませんでした。strict オフの組織、期限切れトークン、別アプリのトークンの応答は未検証です。
4. ダッシュボードの観測使用量セクションは、今日と直近7日間の2回の内訳読み取りだけを行い、60分の間隔で抑制します。日次合計・利用量ページ内訳・観測使用量カードは、それぞれ独立した状態機械を持ちます。

この構成は任意機能であり、有効にする場合だけ、利用者が自分のCloudflareアカウントへAccessアプリケーション、Worker、D1を配置します。配置の順序、Accessを迂回する経路を残さないための条件、リモートD1でのスモークテスト、資格情報のローテーション訓練は[デプロイ手順](deployment.md)にまとめています。サービストークンには有効期限を設定し、期限の1週間前に通知し、ローテーションではSecretだけを更新してClient IDとサーバー側のprincipal定義は変えません。

配置先はWorkers Free、D1 Free、Zero Trust Freeの範囲に限定します。WorkersのCPU上限はWorker自身のJavaScriptの実行時間に対して課され、D1のクエリ待ちは算入されません。算入されるのはAccessアサーションのRS256検証、最大32 KiB本文の`JSON.parse`、`batch()`のための文の組み立て、応答の`JSON.stringify`です。文の数は契約の形で決まり、v1 は日ごとに1文を組むため最大63文、v2 は内訳込みでも4文固定(日次合計、日単位の削除、内訳の挿入、受領記録)ですが、1文あたりのJSON分解は内訳の行数(最大1024行)に比例します。認証を扱うWorkerは典型10〜20 msと案内されているため無料の10 msと同水準であり、この実装の実測はありません。したがって無料枠で成立しうるかは条件的（未検証）であり、デプロイ直後の実機測定（1102件数とCPU時間のP99）で判定します。測定に合格しない場合の設計変更案は「適用しない案」として[デプロイ手順](deployment.md)に置き、それでも収まらない場合は無料枠では成立しないと結論してデプロイを取りやめます。

## データの意味

- 表示するのは観測されたトークン数であり、利用枠や上限ではありません。割合、リング、ゲージ、しきい値は持ちません。
- 日次合計の行はCollectorと日付の組です。同じ日の複数Collectorの行は別々に保持し、合計は受信した値の和として検証します。
- ダッシュボードのカードはプロバイダー別の合計です。複数プロバイダーが関与した行はカンマ結合の1キーとして届き、関与したすべてのカードに加算されるため、カード間で共有分が重複します。カードの合計を足し合わせて全体のトークン数として扱うことはできません。
- 利用内訳は日次合計とは別の読み取りで、日ごとの`attributed ≤ total`が契約です。差分（未分類分）は正確に合計して表示し、過剰紐付けの日は補正せず生の数値で示します。
- 空のキーは「不明」というデータであり、欠陥ではありません。統合せず、そのまま1つのグループとして表示します。
- 鮮度と状態を分離します。`FreshUntil`に相当する概念はなく、Collectorの最終受信時刻だけが鮮度です。12時間を超えると遅延、読み取り失敗時は前回値を保持したstaleです。
- 値がない場合は不明として扱い、ゼロに置き換えません。

## 保存先と設定

アプリのデータルートはOSのユーザー別アプリケーションデータ領域から決定し、マシン固有の絶対パスを設定に埋め込みません。設定にはテーマ、表示言語（ja/en）、更新間隔（5〜15分）、常駐モード、利用量APIのエンドポイント（オリジンのみで秘密ではない）、追加済みプロバイダーの一覧を保持します。旧ビルドの`NotificationsEnabled`と`TokScaleClients`はファイル互換のため読み書きしますが、現行UIに通知の切り替えはなく、旧クライアント一覧はカードの情報源ではありません。プロバイダーURLやClient IDを既定値としてコードに埋め込みません。

アプリは利用量の履歴を保存せず、`settings.json`以外の利用データを書きません。旧版が書いた日別JSONL履歴は読み取りも削除もせず、そのまま残ります。設定ファイルは一時ファイルへ書いてから置き換え、プロセス間の同時書き込みはパス単位のゲートで直列化します。JSONとして壊れたファイルは`.bak`へ退避し、既定値で起動します。

利用量APIの資格情報は設定ファイルに含めず、OS資格情報ストアだけに保存します。ストアが利用不能またはロック中の場合はセッション中のメモリだけに保持し、平文ファイルへは代替保存しません。

## セキュリティ境界

セキュアストアと外部APIとの境界にアクセスできるのは、Infrastructureの資格情報アダプターとUIの読み取りポートだけです。ApplicationとUIが扱うのは不透明な資格情報参照と状態に限り、秘密値をログ、UI、設定へ渡しません。Collectorはsystemdの資格情報ディレクトリからのみ資格情報を読み、コマンドライン引数や環境変数では受け取りません。CLI内部の資格情報を探索してはならず、平文への代替保存も禁止です。

## AOTの制約

UIのcsprojを対象OS上でNativeAOT publishします。Avaloniaのcompiled bindingsを既定とし、JSONのポリモーフィック／リフレクションによるシリアル化にはsource-generated contextを使用します。動的なアセンブリ読み込み、実行時の型探索、トリミングに弱いリフレクション依存を新たに追加しません。InvariantGlobalizationや警告抑制によってAOTの問題を隠しません。

## プロバイダーの取り込み（TokScale）

- プロバイダーカタログはTokScale 4.23.0に固定した開発リポジトリ内の一覧で、内訳が`provider`成分に載せる小文字の紐付けIDだけを持ちます。複数プロバイダーの行はカンマ結合の組み合わせとして扱い、単一プロバイダーのIDとしては扱いません。
- 未知のIDは名称を発明せず、そのまま表示します。空のIDは「不明」です。
- 内訳の数値はTokScaleがローカルログから集計した観測値です。ログの削除（Claude Codeは既定30日）やAPI・キャッシュ型クライアントでは欠落や遅れが生じるため、画面はその注記を常に添えます。
- QuotaSightはプロバイダーへ直接問い合わせません。Codex、Claude、OpenCode Go、GitHub Copilotなどに対する利用枠取得・OAuth・手動入力の経路は削除済みで、現行版には存在しません。
