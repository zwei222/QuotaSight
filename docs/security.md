# セキュリティ

## 脅威モデル

保護対象は、利用量APIのサービストークン（デスクトップアプリのAccess Client ID／Client Secret、Collectorに束縛された資格情報）、Collectorのローカル状態、そして観測されたトークン使用量そのものです。想定する脅威には、同じ端末上の別ユーザーや悪意あるプロセスによる読み取り、ログ・画面共有を介した漏えい、共有範囲を超えた利用量の拡散、送信先の取り違え、ZIPへの秘密情報の混入があります。QuotaSightはサーバーへテレメトリーを送信せず、データを取得できない状態を取得成功として見せません。OSが提供するユーザー境界を超える保護は保証しません。

## 資格情報のライフサイクル

資格情報は必要なときだけセキュアストアから取り出し、リクエストまたは送信処理の短いスコープ内で使用します。WindowsではCredential Manager、Linuxでは`secret-tool`／Secret Serviceを優先します。バックエンドが利用できない場合は現在のセッション中だけ保持し、平文ファイルや設定への代替保存は行いません。接続を削除すると、保存した2つの値（クライアントIDとシークレット）を削除します。資格情報の値を通知、UI、ログ、設定へ渡しません。設定に保存するのは利用量APIのエンドポイント（オリジンのみで秘密ではない）だけです。

Collectorは`CREDENTIALS_DIRECTORY/access-client-id`と`access-client-secret`の2ファイルだけから資格情報を読みます。コマンドライン引数、環境変数、平文ファイルからの読み取りは行いません。復号はsystemdの`LoadCredentialEncrypted=`が行い、Collectorは復号済みの値をその実行中だけ参照します。

以前の版が保存したプロバイダー資格情報（GitHub Appのtoken bundle、OpenAI Codexのtoken、OpenCode GoのAPI keyなど）は、現行版が読み取らず、更新時に自動削除もしません。同じく旧版の利用枠履歴（日別JSONL）も読み取りも削除もせず、そのまま残ります。不要になった旧トークンやAPIキーは、発行元のアカウント設定で失効させてください。ほかのアプリと共用しているキーは、影響を確認してから失効・交換してください。ローカルでも削除する場合は、Windowsの資格情報マネージャーまたはLinuxのキーリング管理画面で、旧版のプロバイダー資格情報と確認できた項目だけを削除します。現行の利用量API用資格情報や用途を特定できない項目は一括削除しないでください。

## ローカルに残るデータ

アプリがディスクへ書くのは`settings.json`だけで、利用量の値、Collector別の受信時刻、内訳は保存しません。設定にはテーマ、言語、更新間隔、常駐モード、利用量APIのエンドポイント、追加済みプロバイダーのIDだけが入り、秘密は含みません。資格情報はOS資格情報ストアにのみ存在します。

Collectorは送信済みrevisionや送信待ちの差分を自分の状態ディレクトリに保存し、利用量APIへは送りません。状態ファイルに秘密は含めず、ディレクトリは所有者のみが読める権限（`0700`）を要求します。

## 通知

現行のUIが出す通知はアプリ内バナーだけです。接続状態、読み取り失敗、stale、トレイ利用不可、常駐モードの保存失敗をここに表示し、いずれも固定文言で、応答本文、URI、識別子を含みません。

デスクトップ通知のバックエンドはビルドに残っています。Windowsの通知バックエンドはWindows App SDK 2.7.0のApp Notifications APIを使用し、`--notification-probe`がサブスクライブ、登録、登録解除、`UnregisterAll`、購読解除のライフサイクルを確認します。Linuxのバックエンドは`org.freedesktop.Notifications`をsession D-Bus経由で呼び出します。ただし現行のアプリ経路からこれらを呼び出す箇所はなく、このビルドはOS通知を送信しません。登録が受け付けられてもポップアップが表示されるとは限らず、Windows実機での表示は未検証です。通常のアプリ終了経路では、登録済みの場合に登録解除と`UnregisterAll`を呼び出しますが、終了処理が実行されない異常終了やcleanup自体の失敗時には、登録情報が残る可能性があります。配布artifactはWindows x64およびLinux x64向けのself-contained .NET 10 Native AOT ZIPのみです。MSIX、deb、AppImageは対象外です。

## 外部送信（日次の利用量スナップショット）

利用量を共有する構成では、ローカルで動作する任意のCollectorから、利用者が設定した利用量APIへ日次のスナップショットを送信します。明示的に構成した場合だけ有効になる任意機能であり、構成しなければ何も送信しません。QuotaSightのlocal-firstの原則は変わらず、この送信先は利用者が指定した自分のAPIです。デスクトップアプリ側は読み取り専用で、利用量を送信しません。

- 送信する内容: バケット日付（`YYYY-MM-DD`、`Asia/Tokyo`区切り）と、その日の合計トークン数です。どちらも集計値であり、内容を含みません。Collectorを `--wire-schema 2` で動かした場合だけ、これに加えて、その日の利用をクライアント・provider・モデル別に分けた識別子（正規化済みの小文字。不明・解釈できない値は空文字）と、5成分（入力、出力、cache read、cache write、reasoning）のトークン内訳を送ります。モデル名を送るのはこのオプトインの経路だけで、既定の v1 は日次合計だけを送ります。受信側は受理した書き込みごとに受信時刻を記録し、読み取り時にCollectorごとの最終受信時刻を返します。
- 送信しない内容: プロンプト、応答本文、ファイルパス、プロジェクト名、セッション識別子、アカウント表示名、ホスト名やユーザー名、コスト・料金、メッセージ数を、どちらの版でも含みません。v2 でも、ローカルの重みファイルのパスやファイル名（`.gguf`、`.safetensors`、`.bin`、`.onnx` で終わる値、`\` を含む値、ドライブレター付きの値、2つ以上の `/` を含む値）はモデル識別子として送らず、空文字に置き換えます。1つの `/` を含む `org/model` 形式だけはモデルIDとして扱います。Collectorは上流のCLI出力から許可した項目だけを写像し、許可外の項目は破棄します。値を推測・切り詰めて送ることはなく、解釈できない値は空文字（「キー不明の利用」）になります。
- v2 の内訳の扱い: 送信するのは上流ツールが既に集計した行だけで、QuotaSightが会話内容から作り直すことはありません。内訳はどのツール・どのモデルをどれだけ使ったかを示すため、日次合計より識別性が高いデータです。送信先は利用者自身が指定した自分のAPIであり、テレメトリーではありませんが、共有範囲を広げたくない場合は v1 のまま（既定）で運用できます。受信側は内訳を日単位の集合として保存し、受理済みより小さい集合では置き換えません。読み取りは所有者スコープと active generation に限定され、内訳は日ごとの合計を超えません（`attributed ≤ total`）。
- 認証: CollectorはCloudflare Accessのサービストークンで接続し、Workers側はAccessが発行するJWTを検証します。検証に必要な設定が欠けている場合、APIは全リクエストを拒否します（fail-closed）。書き込み用と読み取り用はスコープで分離し、Collectorに束縛された資格情報はオーナー全体の読み取りを行えません。未認証、権限不足、対象の不在、一時的な失敗は区別して扱い、どれも「データなし」として表示しません。
- 資格情報の保管場所: クライアントIDとシークレットはOSの資格情報ストア（Windows Credential Manager、Linux Secret Service）にのみ保存し、平文ファイルや設定へは保存しません。Collectorをサービスとして動かす場合は、systemdの資格情報渡し（`LoadCredential`）を使い、設定ファイルやコマンドライン引数に秘密を含めません。アプリの設定に保存するのは利用量APIのエンドポイント（オリジンのみで秘密ではない）だけです。
- 有効期限とローテーション: サービストークンには有効期限を設定し、期限の1週間前に通知されるようにします。ローテーションではSecretだけを更新し、Client IDは変わらないため、サーバー側のprincipal定義は変更しません。猶予期間（1時間〜30日）の間に新旧のSecretを入れ替え、Collectorは`LoadCredential`のファイル差し替えと`systemctl restart`、デスクトップアプリは設定画面からOS資格情報ストアを更新します。手順と確認項目は[デプロイ手順](deployment.md)にあります。
- 運用コストの境界: 受信側はWorkers Free、D1 Free、Zero Trust Freeの範囲で動かす前提であり、有料プランへのアップグレードを前提にしません。そのため認証・検証・応答生成にかかるWorker側のCPU時間が10 msの無料上限に収まるかを、デプロイ直後に実機で判定します（1102の件数とCPU時間のP99）。この判定は未実施であり、無料枠で収まらないと判明した場合の設計変更案は[デプロイ手順](deployment.md)に「適用しない案」として記載し、それでも収まらなければデプロイを取りやめます。無料枠の上限に達した場合は課金ではなくクエリの失敗として現れ、その間は値を取得できなかったものとして扱います。
- Collectorのローカル状態: 送信済みrevisionや送信待ちの差分はCollector側の状態ファイルにのみ保存し、利用量APIへは送りません。状態ファイルに秘密は含めません。
- エンドポイント: 利用量APIのエンドポイントは秘密ではなく、設定画面で入力するオリジンです。パス、クエリ、ユーザー情報、フラグメントを含む値は拒否し、平文HTTPも拒否します。
- 遅延と減少の意味: 送信はリアルタイムではありません。Collectorは1〜6時間間隔で動作するため、表示される値は遅延データです。また、上流の再スキャンで同じ日の合計が小さくなることがありますが、受信側は受理済みの値を下げず、無視した件数を受理応答に記録します。v2 の内訳も同じ規則で、送った内訳の合計が保存済みより小さい日は置き換えず、その日数を `ignoredPartReductions` として返します。したがって減少は「利用が減った」ことを意味せず、再スキャン範囲の違いを意味します。前回値と最終受信時刻を保持し、12時間を超えて古い場合は遅延データとして明示し、権威あるリアルタイム値としては表示しません。

## 外部プロセスと送信処理の安全性

Collectorは外部プロセスを起動せず、上流CLIの出力は運用者のラッパーが標準入力として渡します。自身の引数は固定のオプション名と値として解釈し、shellを起動せず、ユーザー入力をcommand stringへ埋め込みません。標準出力には固定の理由クラスだけを出し、本文、ヘッダー、完全なURL、識別子を出力しません。秘密は標準入力と資格情報ファイルからのみ読み、環境変数やprocess listから探索しません。timeout、キャンセル、最小権限を徹底し、終了後は一時データを破棄します。アプリ側のHTTP読み取りは、リダイレクトを追従せず、cookieを保持せず、既定ヘッダーを持たないクライアントを使います。

## 問題報告時の注意

不具合報告に含めるのは、OS、アプリversion、Collector id、期間、staleかどうか、再現手順、終了コード、redactedされたfield名だけにしてください。token、API key、Authorization header、cookie、完全な応答、個人アカウントを識別する情報は送らないでください。ログを共有する前に秘密値を検索して削除し、必要に応じて最小限の再現データに置き換えてください。
